# ADR-012：模型插件与端侧推理边界

**状态：** Accepted（2026-09-23）
**上游决策：** ADR-009（媒体格式支持矩阵与显式拒绝语义）、ADR-010（跨进程数据面的安全边界与可见性）、ADR-011（保留窗口按 buffer 种类分配）
**相关文档：** [实现状态](../implementation-status.md)、[验证记录](../verification.md)、[契约](../contracts/README.md)、[待办](../TODO.md)、[插件开发](../../plugins/python/README.md)

## 1. 背景与问题

M1（自适应抽帧）与 M3（跨进程数据面）完成后，视频帧**能**按 lease 交给独立进程读字节，
但消费方一直是**验收脚本**——它证明"字节能出去"，不证明"语义链路可用"。
M8 要把一个**真实模型**接到这条链路上，于是必须先回答四个绕不开的问题：

1. **模型身份从哪来？** 写死版本号等于编造溯源，重放同一段素材却换了权重也无从发现。
2. **模型不给置信度怎么办？** 端侧小模型没有校准置信度，填一个数字就是合成业务数据。
3. **observation 凭什么绑定到具体字节？** 没有绑定，"这段描述来自哪一帧"就无法证伪。
4. **插件产物怎么被信任？** 一个可以随意改、digest 随便填的插件，等于没有供应链边界。

本决策用**本机 ollama 上的 `moondream:v2`（VLM，1.7 GB）**作为第一个真实端侧模型接入，
把上述四条落成可执行的规则。选它的理由：它是**端侧**推理（Apple Silicon 上走 Metal，不出网）、
不引入云依赖、且服务本身会报告权重的真实 `digest`。**这一条只承诺"接真实模型"，
不承诺"模型输出可用"**——见 §4 与 §7。

---

## 2. 决策一：模型身份必须来自模型服务实测，读不到就拒绝启动

`plugins/python/processors/vlm-moondream` 的 `configure()` 会向模型服务发 `GET /api/tags`，
从**服务自己报告的条目**里取 `digest`（64 位十六进制），再拼出身份：

| 字段 | 来源 |
| --- | --- |
| `modelArtifactDigest` | `sha256:<服务报告的 digest>`，**不是**插件猜的 |
| `modelReleaseId` | `ollama:<model>@<digest 前 12 位>` |
| `modelId` / `modelVersion` | 从 `name:tag` 拆分 |
| `executionBackend` | `ollama-<GET /api/version 的 version>`（读不到写 `unknown`） |

- 条目不存在 → `model_not_available:<model>`；`digest` 长度不对 → `model_artifact_digest_unavailable`；
  两种情况都**拒绝启动**，不降级到"没有版本也能跑"。
- 验收脚本用自己的 `GET /api/tags` 再算一遍，断言 `provenance.modelArtifactDigest == 服务实测摘要`。
  两者不一致即失败——这条断言才是"溯源"的证据，写死一个版本号不算。

## 3. 决策二：模型不给校准置信度时，必须显式留空并写原因

`moondream:v2` 不返回校准置信度。插件因此**不填 `confidence`**，而是写
`confidence_unavailable_reason = model_does_not_report_calibrated_confidence`。

- 这是**模型的属性**，不是"数据缺失"：任何后续消费方都能区分"这个模型本来就不给"与"这次没算出来"。
- 验收断言同时检查两件事：`confidence` 为空**且**原因非空；只满足一条都不算通过。
- 这条规则对以后接入的任何模型同样成立：给不出校准置信度就写原因，**禁止**用一个看起来合理的数字占位。

## 4. 决策三：observation 绑定到 lease 窗口摘要，锚点不重新计时

- `time_range` 直接取 descriptor 的**半开区间** `[start_ms, end_ms)`，`timing_source=media_pts`；
  插件**不**按自己的墙钟或模型耗时重算时间轴。验收断言 observation 的锚点与源帧完全相等。
- `content_hash` = 该帧 lease 窗口的**摘要**，与数据面给出的 `source_digest` 逐位相等；
  没有它，"这段描述来自哪一帧"就不可证伪。
- `observation_id` 由**稳定输入**派生（stream / source / buffer / 窗口摘要 / modality /
  插件版本 / model release / config hash），重放同一帧得到同一个 ID；验收断言 ID 唯一。
- `config_hash` 是配置的规范摘要（`sort_keys` + 紧凑分隔符），且**不包含** `handoff_endpoint`
  （那是传输位置，不是语义配置）。

## 5. 决策四：插件产物摘要必须可复算，形态决定签名要求

- `tools/plugin_artifact.py` 按**明确范围**复算插件包摘要：
  `pyproject.toml` + `src/**`（排除 `__pycache__` / `.pyc`），**不含** `plugin.yaml` / `README` / SBOM。
  生成时写回 manifest 的 `artifacts.digest` 并更新 `sbom.cdx.json`；`--check` 只校验不回写。
- 插件启动时用 `--expect-digest` 接收期望摘要，自己复算一遍，**不一致即 `exit 2`**
  （防止"manifest 写 A、跑的是 B"）；`artifact_digest` 为空则 `artifact_digest_required` 拒绝配置。
  因此 manifest 里的 `digest` **不允许是占位串**——`make check` 里跑 `--check` 把它变成构建门槛。
- 契约 `docs/contracts/plugin.schema.json` 的 artifacts 增加 `form`（`container` | `local_native`）
  与 `signatureUnavailableReason`：
  - `container`（缺省，兼容既有 manifest）仍**强制** `signature`；
  - `local_native` 要求 `image` 以 `local:` 开头，并**必须**写出不签名的原因。
    本插件的值是 `local_native_plugin_is_not_signed_in_v1`——**写明"为什么不签"，而不是留空假装签过**。

## 6. 决策五：只允许 `cpu_shared_memory`，模型只在本机

- 插件在 `Describe` 里只声明 `acceptsMemoryKinds: [cpu_shared_memory]`。GPU / unified memory
  映射未实现，因此**不声明**它；收到非该 kind 的 descriptor 以 `unsupported_memory_kind:*` 显式拒绝。
- buffer 输入**必须**通过 `edge_material_sdk.LeaseBufferReader` 走真实路径：
  gRPC Acquire → `shm_open` + `mmap` → 摘要校验 → Release。SDK 的 `ProcessorPlugin` 若没挂 reader，
  对 buffer 输入返回 `buffer_reader_not_attached`，**不做**"直接把 buffer 当成没用"的静默跳过。
- 模型只在本机：配置校验要求 `endpoint` 显式写出 host（`endpoint_must_be_explicit`），
  manifest 的 `security.network=allowlist`、`allowedHosts=[127.0.0.1:11434]`、`dataEgress=local_only`。
- 帧字节只出现在"送进模型"这一条路径：不进日志、不进控制消息、不进返回 payload。
  worker **只发现与调用**，不读字节；报告里只用 `segment_name_hint=opaque` 说明"段名存在"，不携带它。

## 7. 后果

### 收益

- 真实链路打通：**四个进程**（编排 / 生产者 runtime / 插件 / worker）协作，`make model-check`
  在授权样本上通过——真实帧 → 本机 VLM → 带锚点、来源、版本与显式置信度语义的 observation。

  | 观察项 | 实测值（`video/1.mp4`，2 帧） |
  | --- | --- |
  | 帧锚点 | `[0,33)`、`[4000,4033)`（与源帧逐位相等） |
  | `content_hash` | `sha256:beabe84d…`、`sha256:97f95fd2…`（= 源窗口摘要） |
  | `modelArtifactDigest` | `sha256:ad0714b7…`（= ollama `/api/tags` 实测） |
  | `executionBackend` | `ollama-0.4.1` |
  | `confidence` | 缺省 + `model_does_not_report_calibrated_confidence` |
  | 单帧端到端耗时 | 0.6–2.2 s（含读字节 + 推理 + 归还） |
  | 账目 | `during: retained_by_kind={audio_pcm:16, video_frame:8}`；`after: released_total=24 retained=0 expired=0 retained_total=24`、`arena_live_slabs=0` |
  | 消费者归还 | `drain.discarded=22 failures=[]`（不消费的音频条目显式 `discard`） |

### 验收暴露的真实缺陷（本轮修掉，不是"一次就过"）

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `model_endpoint_http_404` | `/api/tags`、`/api/version` 是 GET，却被写成 POST | `_request_json(body=None → GET)`，且**不做**"POST/GET 都试"的兜底 |
| 2 | `data_plane_stats_failed:UNAVAILABLE` | 数据面空闲超时 4 s < 单帧推理时间，推理期间无 RPC → 数据面在中途关闭 | 验收 `IDLE_TIMEOUT_MS=60_000` |
| 3 | `handoff_lease_accounting_failed: retained_total=24 released=1 expired=0 still_retained=23` | 消费者只归还了它消费的视频帧，未处理音频条目；数据面要求每条保留都有归宿 | worker 增加 drain 循环显式 `reader.discard()`；验收断言 `drain.failures` 为空且 `discarded>0` |
| 4 | 验收误报"没有匹配的已处理帧 / id 不唯一" | worker 用 proto-JSON 小驼峰（`observationId`），验收脚本按 snake_case 取值 | 验收脚本改读 `observationId`（`frames` 是 worker 自建字典，仍是 snake_case） |

### 代价与已知限制

- **模型输出质量不稳定**：`moondream:v2` 是极小 VLM，同一帧两次推理可能给出不同文本，
  本轮就实测到一次明显的退化输出。本 ADR 只保证**链路语义正确**，不保证**描述可用**；
  换成更强的端侧模型是后续工作，不改变这里的边界。
- `num_predict` 之类采样参数会让该模型输出乱码，因此插件**不传** `options`（模型侧特性，不是通用规则）。
- 单帧串行：`maxConcurrency=maxBatchSize=1`，模型推理期间不并行；吞吐受单帧延迟限制。
- 摘要范围是"`pyproject.toml` + `src/**`"这一确定性约定；README/SBOM 改动不改变插件摘要。

**未验证范围（不得当作已完成）**

- 只在本机回环、`macos-aarch64` 上验收；`linux-x86_64`、Mac mini / 跨机未验证。
- 只有 VLM 一个模型：ASR / OCR / BGE **未接入**；CoreML / Metal 仍 `execution_backend_not_implemented`。
- 插件**未**做 gRPC worker 的 durable 幂等、lease 崩溃回收、沙箱与"无外网"策略的强制执行；
  签名 / SBOM 只有结构预检，没有真实验签。
- `golden_path_verified` 恒为 false；2–5 秒的语义可见性未测；小时级长直播未测。
- 未验证同一素材在**换模型 / 换配置**时 `observation_id` 与 `config_hash` 的分辨力（只有单配置实测）。
