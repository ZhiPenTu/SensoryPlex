# ADR-010：跨进程数据面的安全边界与可见性

**状态：** Accepted（2026-09-23）
**上游决策：** ADR-008（Apple Silicon 是一等端侧目标）、ADR-009（媒体格式支持矩阵与显式拒绝语义）
**相关文档：** [实现状态](../implementation-status.md)、[验证记录](../verification.md)、[契约](../contracts/README.md)、[待办](../TODO.md)

---

## 1. 背景与问题

M3 把"解码 → arena → `BufferDescriptor` → lease"从**同进程内**推到了**跨进程**：
Runtime 把已解码的 buffer 留在共享内存里，独立的消费进程（`tools/handoff_worker.py`，
真实验收见 [验证记录](../verification.md)）通过 gRPC 领取一个读取窗口，读字节、校验摘要、显式释放。
落地时用的是 POSIX 共享内存（`shm_open` + `mmap`，`crates/media/src/shm.rs`）。

这带来一个必须写下来的问题：**共享内存段不是访问控制**。同一台机器上、同一 UID 的任何进程
都能 `shm_open` 到那个段（只要猜到或看到段名），把整段映射进自己的地址空间，然后读到**相邻** buffer
的字节 —— lease 只约束"该不该读那个窗口"，不约束"能不能读到那些字节"。
如果不在决策里写清楚，后续很容易把 lease 误当作内存隔离，或把段名误当作授权凭证。

这一条不是推测，而是验收链路的**已声明限制**：消费者进程（`tools/handoff_worker.py`）本来就以
`shm_open` + `mmap` 把整段映射进自己的地址空间，它证明的是"按 lease 读对了窗口、摘要对得上、
释放有出口"，而不是"读不到别的字节"。脚本把这一点写进结果文件（`same_uid_segment_visibility`），
编排脚本也把它作为已知边界读取，而不是当成缺陷。

本 ADR 没有做对抗测试（没有写一个恶意同 UID 进程去抢读相邻 buffer），因此这里给出的是**设计结论 +
已声明限制**，不是"已验证无法读"。目标也不是"让共享内存变安全"，而是**把它的边界写成明确、
不被误解的约束**，并说明需要更强隔离时应该换什么方案。

---

## 2. 决策一：lease 是生命周期协议，不是内存隔离

- lease 保证四件事，且只保证这四件事：**窗口落在该 buffer 内**（越界拒绝，不夹取）、
  **摘要绑定被授予的窗口**（不是整段）、**同一 buffer 同时只有一个消费者**、**TTL 到期后回收**。
- lease **不**保证：其他同 UID 进程读不到字节、buffer 之间存在内存屏障、读者不能改动段内容。
- 因此：消费进程是**受信组件**，与 Runtime 同信任域。验收脚本把这条限制作为显式注记上报
  （`same_uid_segment_visibility`），不伪装成已实现的安全边界。

## 3. 决策二：段名按运行随机，且不出现在报告里

- 段名由 `run_seed()`（系统时间 + pid + ASLR 地址）派生，经 SHA-256 截断为 `/sp.<12 位十六进制>`：
  每次运行都不同，**不可从 arena handle 或 `ReplayReport` 推导**（单测
  `segment_names_differ_between_runs` 覆盖）。
- 段名只在 lease 服务的应答里出现（`ListRetainedResponse.segment_name`），
  `ReplayReport` 里只有不透明 `arena_id`/`locator.handle`，**没有段名**。
- macOS 的 `PSHMNAMLEN` 是 31，段名按 `< 24` 字符断言，不用长名。
- 这条降低的是"顺手读到"的概率（无法凭空猜出段名），**不是**抗恶意同 UID 进程的隔离，
  因此不能作为安全结论引用。

## 4. 决策三：数据面只在本机回环上暴露

- `--handoff-listen` 必须解析成回环地址，否则 Runtime 直接拒绝启动
  （`handoff data plane is host-local; refusing non-loopback listener`）。
- 共享内存不可跨主机映射，跨机只能换传输方式（SRT / gRPC 流 / 对象存储），
  不能把这条路径当成"分布式数据面"。
- 段在生产者退出时 `shm_unlink`；消费者只 `munmap` + `close` 自己的映射，不删名
  （删除段名不影响已映射的读者，这一点写进了 `ShmSegment::drop`）。

## 5. 决策四：控制消息只带受控引用

- gRPC 消息里只有不透明句柄、`offset_bytes`/`length_bytes`、`sha256:` 摘要、时间区间、
  `BufferFormat` 与 lease 标识；**没有**帧、PCM、tensor、宿主路径、密钥（AGENTS.md）。
- 拒绝一律走 `ProcessingError.reason_code`，不用日志代替契约。稳定拒绝码分两类：
  - 保留期（有界容量）：`handoff_backlog_full`、`arena_capacity_exceeded`；
  - 消费期（请求非法）：`mapping_out_of_range`、`ambiguous_window`、`unknown_buffer`、
    `invalid_lease_ttl`、`buffer_already_leased`、`unknown_or_released_lease`。
- 参数越界不夹取：保留表上限 `<= 4096`、TTL 限定 `[50, 60000] ms`、单条 buffer 区间不超过 60 s。

## 6. 决策五：有界性必须能对账

任何"有上限"的说法都必须落到两条恒等式（消费者与编排脚本各算一遍）：

```
retained_total = retained + released_total + expired_total   # 每条保留的 buffer 都有归宿
offered_total  = retained_total + retain_rejections          # 每个保留请求都有结果
```

外加 `arena_live_slabs == 0`（运行结束时没有悬挂 slab）与 `offered_total == ReplayReport` 的交接样本数。
只报"健康"不算证据。

## 7. 后果

- 收益：模型 worker 可以独立进程/独立解释器运行，不必把字节拷进控制消息；
  容量与 lease 生命周期都有上限和可观察语义。
- 代价：同 UID 信任域内没有逐 buffer 隔离；段名可见即字节可见，不能用它承载密钥类数据。
- 如果将来需要真正的隔离，应换机制而不是加固段名：**进程隔离（不同 UID / sandbox / 容器）**、
  `memfd` + `F_SEAL_*`（Linux）或改回 socket/管道流式传输。
  这些都属于新 ADR 的范围，不在本决策内。

**未验证范围（不得当作已完成）**

- 未验证跨用户、跨主机、容器内外的可见性差异（Linux/x86_64 侧尚未验收，见 `docs/TODO.md` M6）。
- 未验证长时间运行下的段泄漏（多次 replay 反复创建/删除段只在单次验收里观察）。
- 未验证 macOS 上"进程崩溃后段名残留"的具体行为与清理策略。
