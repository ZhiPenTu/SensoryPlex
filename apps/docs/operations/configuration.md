# Configuration

All runtime configuration lives in the repository-root `.env`, which is generated by `make configure`, is
git-ignored and must never be committed. `.env.example` documents the full set of keys; this page explains
what each one changes and how the system behaves when it is wrong.

## Ports and bind addresses

| Variable | Default | Notes |
| --- | --- | --- |
| `CONSOLE_PORT` | `5173` | Web console |
| `API_PORT` | `8091` | Business/admin/identity API |
| `GATEWAY_PORT` | `8090` | Compatibility entry |
| `DOCS_PORT` | `5174` | This documentation site |
| `DOCS_DEV_PORT` | `5175` | `make docs-dev` / `docs-serve` only; never used by the served site |
| `POSTGRES_PORT` | `25432` | Metadata store |
| `NATS_PORT` | `24222` | Event bus client port (monitor: `28222`) |

Host bindings are loopback-only. The index search face (`index:50077`) is reachable inside the compose network
and deliberately not published to the host.

## Credentials

| Variable | Required | Purpose |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | Yes, no default | Postgres password; compose aborts if unset |
| `SENSORYPLEX_DATABASE_URL` | Yes | Full DSN, including the password |
| `SENSORYPLEX_API_TOKEN` | Yes, no default | Single-deployment API token; compose aborts if unset |
| `SENSORYPLEX_PRINCIPAL` | `local-developer` | Principal the deployment token maps to |
| `SENSORYPLEX_INDEX_AUTH_TOKEN` | Yes for the events profile | Read by the search face; length ≥ 32 |
| `SENSORYPLEX_INDEX_SEARCH_TOKEN` | Yes for the events profile | Read by the API; the **same** token as above |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | Reserved | Present in the example for the object-storage path, which is not implemented |

`make configure` fills the random values. The two required-without-default keys use compose's
`:?Run make configure` guard, so a missing value fails the whole stack immediately instead of starting with a
blank credential.

::: warning One token, two names
`SENSORYPLEX_INDEX_AUTH_TOKEN` and `SENSORYPLEX_INDEX_SEARCH_TOKEN` are the **same** token seen from two
processes. Giving only one of them makes the API refuse to start; giving neither is allowed, and the API then
reports semantic search as explicitly unavailable rather than pretending it works.
:::

## Event chain tiers

The tier sets the inflight cap, and both batch depths must be **less than or equal to** it:

| Variable | Default | Meaning |
| --- | --- | --- |
| `SENSORYPLEX_RESIDENT_TIER` | `medium` | Machine tier used for admission |
| `SENSORYPLEX_EVENT_QUEUE_CAPACITY` | `32` | Per-tier inflight cap |
| `SENSORYPLEX_EVENT_RELAY_BATCH` | `16` | Rows the relay claims per round |
| `SENSORYPLEX_EVENT_CONSUME_BATCH` | `32` | Inflight unacked messages on the consumer |

Failure semantics are strict on purpose:

- a batch above the cap ⇒ the service **refuses to start before connecting to anything**, with
  `event_inflight_exceeds_tier_cap`;
- a missing variable ⇒ an explicit `not_injected`;
- values are never clamped and the tier is never silently downgraded.

## Retrieval

| Variable | Default | Meaning |
| --- | --- | --- |
| `SENSORYPLEX_INDEX_SEARCH_ENDPOINT` | `index:50077` | Search face address. Inside containers it must be the compose service name — `127.0.0.1` there means the container itself |
| `SENSORYPLEX_INDEX_VECTOR_INDEX_KEY` | `material_text_bge_small_zh_v1_5_d512_v1` | Collection key; encodes the model and dimension contract |

The collection key is a contract, not a label: the search face guards on the model release that built the
collection, so changing the encoder without changing the key is refused rather than mixed.

| Variable | Default | Meaning |

| `REPO_ROOT` | `../../` | Repository root bind-mounted into `api`/`gateway`/`console`; set it to the absolute path for reproducible containerised validation |
| `MEDIA_DIR` | `/tmp` | Directory of authorised samples, mounted read-only at `/host-media` |

| `RUST_LOG` | `info` | Rust log filter |

## Demo account

| Variable | Notes |
| --- | --- |
| `SENSORYPLEX_DEMO_USERNAME` | Set by `make demo-seed`; the login page shows the demo button only when this is present |
| `SENSORYPLEX_DEMO_PASSWORD` | Random password written to `.data/demo-password` |

Demo credentials are privileged (`admin`, `operator`). On production-like nodes leave both empty so the login
page falls back to "an administrator must create the first account".

## Documentation site

| Variable | Default | Meaning |
| --- | --- | --- |
| `DOCS_PORT` | `5174` | Host port for the `docs` service |
| `DOCS_DEV_PORT` | `5175` | Host port for `make docs-dev` / `make docs-serve` |
| `DOCS_BASE` | `/` | **Build-time.** Path prefix for an artifact hosted under a sub-path |
| `DOCS_SITE_URL` | empty | **Build-time.** When set the build emits a sitemap with absolute URLs; empty means "not published" |

`DOCS_BASE` and `DOCS_SITE_URL` are passed on the command line (`make docs-build DOCS_BASE=/repo/`), not
read from `.env` by the `docs` service: the local service always serves the site from the root of
`127.0.0.1:5174`. A sub-path artifact lands in `apps/docs/.vitepress/dist` and is deliberately **not**
copied into the running container, because its absolute links would all 404 behind a root-path nginx.
`DOCS_SITE_URL` is wired into the image build (it only adds sitemap/absolute URLs); `DOCS_BASE` is not.

## Operational rules

- `.env` is git-ignored and must stay that way. Never paste a generated `.env` into an issue, a screenshot or
  a container log.
- Rotating a credential means regenerating it in `.env` and restarting the services that read it — some
  (like the index search face) are validated at startup, so a stale process keeps using the old value.
- The repository `/workspace` bind mount inside containers is a view of the host tree. A container cannot
  write new credentials back to the host `.env`; that is why `make configure` is a host-side target.
