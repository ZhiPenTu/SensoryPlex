# 时间轴语义

时间是整套系统里最硬的契约，所以规则也最严。

## 区间规则

所有时间值都是**恰好落在同一条 stream 上的半开区间 `[start_ms, end_ms)`**，单位是相对该 stream 原点的
毫秒偏移，且 `end_ms` 必须严格大于 `start_ms`。

由此得到：

- 相邻区间不会重复计算边界瞬间；
- 不同 stream 的区间不能在未声明的情况下互相比较——偏移是 stream 相对的；
- 框架绝不用夹取的方式“修复”可疑区间；未知或缺失的值保持未知。

## 锚点是呈现顺序，且不携带字节

`TimelineAnchor` 是某条 stream **呈现**顺序上的区间，其 `pts_ms` 等于区间起点。锚点是一种引用：
它只带坐标，不带媒体字节。

`ffprobe` 按**解码**顺序输出帧，含 B 帧的流会出现 PTS 非单调。运行时把它们重排为呈现顺序，并把移动过的
数量记入 `out_of_order_items`。重排是被统计的显式动作，不是静默修复。

## 每个被丢弃的点都有原因

抽样是自适应的，所有没被保留的点都以原因码计数，例如：

| 原因 | 含义 |
| --- | --- |
| `collapsed_interval` | 该区间在当前密度下没有被抽样保留 |
| `duration_unknown_last_frame_interval` | 最后一帧区间的时长未知 |
| `pts_unavailable` | 没有可用的可靠呈现时间戳 |

时长未知、PTS 未知或超出声明时长的点都会被如实上报——绝不夹取成一个看起来合法的区间。

## 解码数据平面要么是真的，要么全零

只有在本次构建真的解码了媒体时，才会填充 `ReplayReport.decoded`：

- **全零等于“没有解码发生”。** `arena_id` 为空时，不允许出现 `tracks`、`evidence_descriptors` 或非零的
  `descriptors_built`。一个填满零的结构不是成功。
- `first_pts_ms` / `last_end_ms` 用 `-1` 表示“未观察到”——绝不用 `0`，那会冒充 stream 原点。
- `timeline_offset_ms` 记录从原始时间戳减去的呈现原点（容器带 edit list 时非零），使 descriptor 与
  `ffprobe` 锚点处在同一条呈现时间轴上。
- `overlapping_samples` 统计区间重复上一段的 buffer：载荷是真实的，因此保留——但要计数。

## 音频与实时的特殊约定

- 音频按 5 秒窗口切段。插件严格按 descriptor 里上报的 `sample_format` 解释字节；未知布局显式拒绝。
  既没有默认采样宽度，也没有“按 4 字节/样本硬读”的兜底。
- 越出所属窗口的子段只**标记**，不夹取。
- 直播没有已知时长，因此不产出锚点区间。断流会被测量，重连归解码元素
  （`srtsrc auto-reconnect`），不在流水线里重造一遍。

## 为什么要这么严

一个时间语义是近似的素材库，既回答不了“00:12:30 发生了什么”，也不能作为证据使用。这里的严格正是
区间查询、时间轴融合与原片区间回放三者能够互相一致的原因。
