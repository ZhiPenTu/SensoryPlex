# 控制台全流程

Web 控制台是唯一的产品面。本页走一遍 上传 → 任务 → 素材 → 回看 的闭环，并说明每个界面在能力缺失时会
报告什么。

## 开始之前

```sh
./deploy/up.sh && ./deploy/up-events.sh     # 控制面 + 常驻事件链路
make demo-seed                              # 供登录页使用的演示账号
make task-worker-daemon                     # 宿主常驻工作器
```

## 界面清单

| 路由 | 界面 | 用途 |
| --- | --- | --- |
| `/assets` | 视频库 | 导入媒体、查看准入状态 |
| `/jobs` | 处理任务 | 关联已发布方案创建并启动任务 |
| `/materials` | 素材检索 | 查询切片、读取观测、回看原片 |
| `/plugins` | 插件 | 插件配置版本与校验结果 |
| `/nodes` | 节点 | 节点拓扑、安装位置与预检结果 |
| `/pipelines` | 方案 | 编排方案草稿与发布 |
| `/users`、`/audit`、`/access`、`/system` | 管理 | 账号与角色、审计轨迹、作用域凭据、系统状态 |

## 1. 导入媒体 —— `/assets`

用演示账号登录，进入 **视频库**，点「导入视频」。支持 `.mp4` 与 `.webm`。上传完成后该行状态是「待准入」
——文件存在且可寻址，但还没有跑过任何推理，也就不存在素材。控制台不会预先造一条素材记录来把货架填满。

## 2. 创建并启动任务 —— `/jobs`

进入 **处理任务**，新建任务，把上传的视频与一个**已发布**方案关联（内置 OCR 方案适合作为第一个），
然后点「开始处理」。

任务只有在下列条件都成立时才可分发：

- 方案存在已发布、不可变的 revision；
- 目标节点在线且已通过预检；
- 节点满足方案的 placement 与数据本地性约束。

任一条不成立时控制台会显示具体未满足的前置条件。节点缺失按“节点离线”（HTTP 503 语义）上报，
而不是排一个永远静默等待的队列。

## 3. 让宿主工作器干活

```sh
make task-worker-status     # 常驻工作器还活着吗
```

宿主工作器保持同机 `local-host` 节点的心跳，消费 `task_process` 任务意图，用 GStreamer 解码，
用 RapidOCR 提取文字观测，把观测融合到时间轴，事务性追加入库，最后把任务标记 `completed`。
正是这个完成动作触发向量化，并让该素材的检索面就绪。

## 4. 读取结果 —— `/materials`

当该行变成「查看素材」后，素材检索界面提供：

- **按时间轴对齐的切片** —— 每一行是源 stream 的一个 `[start_ms, end_ms)` 窗口，挂着它的观测；
- **文字观测** —— OCR 文字块及其帧像素坐标与产出它的模型发布版本；
- **筛选** —— 关键词（字面子串）、标签（AND）、时间范围（区间重叠），modalities 之间是 OR；
- **历史版本** —— 查询旧 revision 时动态标记 `superseded`，原始快照保持不可变；
- **原片回放** —— 对选中区间做 HTTP Range 流式回放。

`./deploy/up-events.sh` 起起来、且该素材已向量化之后，这里才会出现语义模式。没有检索面时 API 显式
报错，绝不返回一个降级的假排名。

## 哪些是刻意报告为不可用的

- 索引进程未启动前的语义检索。
- 本平台缺失后端的能力——原因来自 `unavailable_reason` 原文渲染，不会被换成一句通用话术。
- 管理界面里尚未接线的媒体准入与执行路径。底座不会把一个没实现的功能渲染成能用的样子。

## 验收

```sh
make golden-path-check
```

九个场景：鉴权、节点就绪、视频上传、方案发布、任务分发、端侧计算、向量落库、语义检索、原片回看。
这个检查没有在真实媒体上成功跑过之前，不要描述该闭环已完成——见
[能力实现状态](/zh/reference/status)。
