# 项目简介

SensoryPlex 是**端侧 AI 多模态素材预处理框架**。它接入媒体文件与 SRT 直播流，在持有加速器的那台机器上
解码，由彼此独立的模型插件产出观测，再把观测融合到同一条时间轴上，连带血缘一并入库，最后回答那些能够
追溯到原片可回放区间的区间查询。

交付形态是 **Web 控制台**，不做桌面客户端。它背后是一个主节点（控制面，容器化）与可选的 worker 子节点，
子节点可以与主节点同机，也可以在同一局域网内的其它主机上（ADR-026）。

## 它解决什么问题

把视频变成可检索素材的常见做法只有两种：云端流水线（丢失本地性、成本可控性和“结论从哪来”），或者一堆
脚本（说不清哪条结论由哪个模型版本给出，也无法复现）。SensoryPlex 的立场是：

- 价值的**单位**是 `MaterialUnit` revision：同一 stream 上不可变、可寻址的一段，并且记录了来源与产出它的
  模型发布版本；
- 结论的**质量取决于证据**：每条观测都带时间范围、产出身份，以及显式的置信度状态；
- **未知本身就是一等值**：PTS 未知、时长未知、模型置信度缺失都按未知上报，绝不用“看起来很合理”的默认值
  替代。

## 设计原则

下面这些规则是被代码、契约与评审强制执行的，不只是写在文档里：

1. **`proto/` 是唯一的跨语言契约源。** Rust 在 `build.rs` 生成 tonic/prost 代码，Python 绑定与控制台类型由
   `make proto` 生成。禁止手改生成代码——本仓库自己的生成产物同样适用。
2. **时间轴是同一 stream 上的 `[start_ms, end_ms)`。** 半开区间、毫秒偏移、终点必须大于起点。为了让区间
   看起来合法而夹取数值是禁止的。
3. **置信度缺失就是未知。** 不用 `0` 或 `1` 代替“没有意见”，并且必须说明缺失原因。
4. **禁止合成业务成功数据。** 工程底座不生成模型结果、图表序列或分钟值；空结果就是空结果。
5. **原始媒体不离开数据面。** 帧、PCM 与 tensor 由有界共享内存 lease 寻址；控制消息、事件与日志只携带
   受控引用。
6. **所有队列与并发都有上限，所有失败都可观察。** timeout、取消、重试与拒绝语义都是显式的。
7. **能力必须如实上报。** 不可用的后端必须带必填原因；健康检查通过绝不意味着端到端链路可用。
8. **迁移只追加**，并通过 `tools/migrate.py` 显式执行；历史 revision 不可覆盖。

## 受支持平台

项目只承诺真正验证过的组合。

| 平台 | 状态 | 说明 |
| --- | --- | --- |
| `macos-aarch64`（Apple Silicon，含 Mac mini 端侧部署） | 受支持 | 加速进程原生运行；容器访问不到 Metal/CoreML，因此模型插件在宿主执行。 |
| `linux-x86_64`（NVIDIA 性能主线） | 受支持 | 控制面容器化；`cuda` 加速器探测与 NVIDIA 侧验收**未验证**。 |
| `linux-aarch64` | 控制面受支持 | 仅容器形态。 |
| Windows | 非一等目标 | 仅可通过 WSL2/Docker 兼容运行。 |

共享内存、DMA 与 CUDA/Metal 句柄严格 host-local。因为局域网拓扑，原始媒体不经 NATS 传输。

## 0.1.0 是什么

**可运行工程底座**：带不可变 revision 与血缘校验的事务性素材元数据、带鉴权的关键词/标签/时间范围查询、
真实 GStreamer 解码进有界 arena 并完成 lease 签发/校验/释放、音频切段与带逐点原因的抽帧、带重连测量的
SRT 实时接入、四个端侧模型插件（VLM / ASR / OCR / BGE）、向量落库与检索、经确认才写 `published_at` 的
事务性 outbox + JetStream 常驻消费、Web 控制台，以及带预检、部署意图、审计与回滚的局域网节点拓扑。

::: warning 现在还**不是**什么
- 真实媒体端到端 Golden Path **未验收**，`golden_path_verified` 保持 `false`。
- Rust 侧**没有任何 in-process `ExecutionBackend`**：`model_inference` 目前恒在
  `unavailable_capabilities` 里。
- NATS 任务分发**未接线**；已发布链路只到 outbox → JetStream → index sink。
- 模型到素材的自动来源映射未实现。
- 服务端 Milvus 拓扑**未验收**（本机 Docker Hub 不可达）；已验证形态是 Milvus Lite，而它是进程独占的。
- 生产级跨机 mTLS 证书轮换与主节点高可用选主属于后续阶段。
:::
