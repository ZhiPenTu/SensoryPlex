## Where the project stands

SensoryPlex **0.1.0** is a runnable engineering base, not a finished product. It ships the Rust runtime
with real GStreamer decode, the Python AI SDK and four edge model plugins, an append-only PostgreSQL
model with immutable material revisions, a transactional outbox into NATS JetStream, a resident vector
index with a gRPC search face, a Web console, and a node topology for LAN worker sub-nodes.

::: warning Status statements on this site are scoped
`ReplayReport.golden_path_verified` is currently **false** in the default report. Real-media end-to-end
validation, model-to-material source mapping and server-side Milvus are **not verified**. Anything
described as "not verified" here is exactly that — see [Capability status](/reference/status) for the
per-area evidence boundary before you rely on any part of the stack.
:::

## Is this for you?

- **You want a local material library with evidence.** You need to answer "what is in this video, when,
  and which model said so", with the original frame range still playable.
- **Your compute is heterogeneous.** Accelerators live on a Mac mini, an NVIDIA box or a vendor NPU
  host, and you do not want to re-implement every model to fit one container runtime.
- **You care about auditability more than feature count.** You would rather see `unavailable` with a
  reason than a zero-result success.

If you want a turnkey hosted media AI product, this is the wrong layer — it is the substrate underneath
one.
