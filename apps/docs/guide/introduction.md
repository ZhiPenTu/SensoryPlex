# Introduction

SensoryPlex is an **edge-side multimodal material preprocessing framework**. It ingests media files and
SRT live streams, decodes them on the machine that owns the accelerator, produces observations from
independent model plugins, fuses those observations onto one timeline, stores them with lineage, and
answers region queries that can be traced back to a playable frame range of the original media.

The product shape is a **Web console** — there is no desktop client. Behind it sits a main node
(control plane, containerised) and optional worker sub-nodes that may live on the same machine or on
other hosts in the same LAN (ADR-026).

## The problem it solves

Turning video into searchable material is usually either a cloud pipeline (you lose locality, cost
control and the ability to say where a conclusion came from) or a pile of scripts (you cannot say which
model version produced which claim, or replay it). SensoryPlex takes the position that:

- the **unit of value** is a `MaterialUnit` revision: an immutable, addressable slice of one stream,
  with the source and the producing model release recorded;
- a **conclusion is only as good as its evidence**: every observation carries its time range, its
  producing identity and an explicit confidence state;
- **unknown is a first-class value**: an unknown PTS, an unknown duration or a missing model confidence
  is reported as unknown, never substituted with a plausible default.

## Design principles

These rules are enforced in code, contracts and review, not just documented:

1. **`proto/` is the only cross-language contract source.** Rust generates tonic/prost code in
   `build.rs`; Python bindings and console types are generated by `make proto`. Hand-editing generated
   code is forbidden, and the same rule applies to this repository's own generated files.
2. **The timeline is `[start_ms, end_ms)` on one stream.** Half-open, millisecond offsets, end greater
   than start. Values are never clamped to make an interval look valid.
3. **Missing confidence is unknown.** A confidence of `0` or `1` is never used to stand in for "no
   opinion"; the reason for the omission must be stated.
4. **No synthetic success data.** The engineering base does not fabricate model results, chart series or
   minute values. An empty result is an empty result.
5. **Raw media never leaves the data plane.** Frames, PCM and tensors are addressed by bounded
   shared-memory leases; control messages, events and logs carry references only.
6. **Every queue and concurrency limit is bounded, and every failure is observable.** Timeouts,
   cancellation, retry and refusal semantics are explicit.
7. **Capability is reported truthfully.** An unavailable backend carries a mandatory reason; a passing
   health check never implies that an end-to-end path works.
8. **Migrations are append-only** and executed explicitly through `tools/migrate.py`. Historical
   revisions are never rewritten.

## Supported platforms

The project only promises combinations it has actually exercised.

| Platform | Status | Notes |
| --- | --- | --- |
| `macos-aarch64` (Apple Silicon, incl. Mac mini edge deployment) | Supported | Accelerated processes run natively; containers cannot reach Metal/CoreML, so model plugins run on the host. |
| `linux-x86_64` (NVIDIA main line) | Supported | Control plane is containerised; `cuda` accelerator probing and NVIDIA-side acceptance are **not verified**. |
| `linux-aarch64` | Supported for the control plane | Containers only. |
| Windows | Not a first-class target | Only through WSL2/Docker compatibility runs. |

Shared memory, DMA and CUDA/Metal handles are strictly host-local. Raw media is never transported over
NATS because of the LAN topology.

## What version 0.1.0 is

A runnable engineering base: transactional material metadata with immutable revisions and lineage
validation, authenticated keyword/tag/time-range queries, real GStreamer decode into a bounded arena with
lease issue/verify/release, audio segmentation and adaptive frame sampling with per-drop reasons, SRT
live ingest with reconnect measurement, four edge model plugins (VLM / ASR / OCR / BGE), vector storage
and retrieval, a transactional outbox confirmed into NATS JetStream plus a resident consumer, a Web
console, and a LAN node topology with preflight, deployment intent, audit and rollback.

::: warning What it is not yet
- Real-media end-to-end golden path is **not verified**; `golden_path_verified` stays `false`.
- There is **no in-process `ExecutionBackend`** in Rust: `model_inference` is permanently listed in
  `unavailable_capabilities` today.
- NATS task dispatch is **not wired**; the published path is outbox → JetStream → index sink only.
- Model-to-material automatic source mapping is not implemented.
- Server-side Milvus topology is **not verified** (local Docker Hub was unreachable); the verified form
  is Milvus Lite, which is process-exclusive.
- Production-grade cross-host mTLS rotation and main-node HA election are future work.
:::
